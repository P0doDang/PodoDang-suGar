# rephase 비교 결과

rephase에서 rephase 단계가 실제로 해를 줄인 큐브 200개를 골라, 같은 스크램블에서 다른 알고리즘 4개와 비교한 결과다.

## 실험 조건

| 항목 | 값 |
|---|---|
| 기준 알고리즘 | rephase: kociemba Two-Phase 첫 해(최대 24수) + rephase 최대 100 ms |
| rephase 설정 | window 8, boundary+sliding, HTM |
| 스크램블 | 30수, seed 1부터 순서대로 (stemil shuffle) |
| case 선정 | seed 1~63968의 63,968개 중 rephase 성공 200건 (0.31%) 중 앞 200건 |
| stemil | 원본 stemil, 500 ms |
| kociemba | pip kociemba(C two-phase), 첫 해(최대 24수) |
| kociemba_sym | hkociemba RubikTwoPhase(대칭 축소), 첫 해, 6스레드 |
| optimal | IDA* 최적해, case당 최대 60초, 6스레드 |

## rephase와의 차이

차이는 `rephase - 다른 알고리즘`이다. move 차이가 음수면 rephase가 더 짧다.

| stemil | -0.54 | 110 | 62 | 28 | -35.94 | -374.75 | -2064.03 |

## 측정 규칙

- **최종 해까지 시간:** 최종 해가 처음 존재한 시각을 사후에 잰 값이다. 모든 알고리즘에 같은 규칙을 쓴다. rephase는 가장 좋은 Two-Phase 해를 찾은 시각에 rephase가 개선한 시각의 오프셋을 더한다. stemil은 마지막 개선 시각이고, kociemba·kociemba_sym·optimal은 한 번의 호출 시간이다.
- **실행 시간:** 실제로 걸린 시간이다. 6way·stemil·stemil_rephase는 Two-Phase 시간 예산을 끝까지 쓴다.
- **메모리:** 테이블을 포함한 프로세스 peak RSS다.
- **실행 방식:** 알고리즘은 하나씩 순서대로 실행하고, 시간은 테이블 로딩 이후부터 잰다.
- **주의:** case는 rephase의 rephase가 성공한 큐브만 고른 것이다. rephase에 유리한 표본이며, 무작위 큐브 전체의 평균과는 다르다.
